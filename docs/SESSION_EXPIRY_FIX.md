# 登录会话过期闪动修复

2026-11-16。

原因：认证装饰器在会话超过一小时后重定向到登录页，但旧的 `authenticated` 标记仍保留。基础模板因此在登录路由渲染控制台框架而没有登录表单，并继续加载状态。状态接口再次重定向，造成空白登录页反复加载。直接访问登录地址时携带有效登录标记也会隐藏表单。

修复：

- 请求入口清除已过期的认证标记和登录时间，保留 CSRF，使已经打开的登录表单仍可提交。
- 模板使用经过有效期校验且排除登录路由的认证显示状态。登录页不渲染控制台或启用状态轮询。
- 前端识别会话失效后停止状态刷新，使用替换导航跳到登录页，不将跳转误报为网络失败。

验证：120 项 Python 测试通过；新增七项过期登录和重新认证回归检查。隔离浏览器验证过期 Cookie 直接访问和状态轮询中途过期，分别观察 16 秒，未产生重复请求，JavaScript 错误为零。部署后的实际 HTTP 服务也使用过期签名 Cookie 验证了登录表单可见、状态轮询缺席及过期认证清除。

只更新 `web.py`、`templates/base.html`、`static/app.js` 并重启网页服务。邮件监听进程保持不变，未发送测试邮件。部署前保留回滚备份。

浏览器回归脚本：`scripts/verify-session-expiry.py`。
